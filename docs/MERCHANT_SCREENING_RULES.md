# 幣商篩選規則 · 2026-10-21

使用者最新指定的營運篩選，由 `scripts/merchant-screening.mjs` 實作；此模組不修改正式身分名冊或直接計算營收。

1. 使用會員頁的累計「總儲值」，不可用單月排行或不完整月份加總冒充累計。缺值保持未知。
2. 同一平台、單一月份的不同交易對象達 **20人以上** 即保留，累計官儲超過10,000元亦適用。計算收或贈的不同AID聯集，不含自己，不用筆數，不跨月加總。
3. 本期未達20人但歷史某個月已達者，另列歷史廣度保留，避免抹除歷史證據。
4. 累計官儲低於1,000元保留為低額線索；只有0–2個對手者另列角色／庫間結算待核，避免直接當成零售幣商。
5. 1,000～10,000元且未達交易廣度條件者待核。嚴格「破萬」為 **大於10,000**，剛好10,000元不直接排除。
6. 超過10,000元、當期已完整覆蓋月初至比較截止日、且未見當期或歷史20人條件者，依營運規則排除。
7. 只有七日資料時，七日已達20人可證明該月已至少20人；七日未達，不能證明整月未達，保留覆蓋缺口。
8. 已明確確認的直播主優先另列。既有使用者確認的幣商身分，與本次模型保留名單分開。

「只完成首儲」是使用者提供的營運線索。未核對逐筆儲值明細前，累計金額不能被轉成「恰好一筆首儲」；輸出保留 `firstDepositCount: null`。模型保留亦不等同新增正式身分確認，`includeInActualRevenue` 固定為 `false`。
