# 給 GROK 的接手指令

請接手這個營運儀表盤，先讀 `README.md`、`docs/grok-handoff-20261021.json` 和 `UPDATE_WORKFLOW.md`，不要重新製作網站，也先不要改外觀。

1. 分清楚 GitHub 程式與原機器私有資料。若你沒有原機器檔案、Node 與已授權 Chrome 工具，先說明限制；不要宣稱可以僅靠後台網址接管已登入視窗。
2. 目前全年歷史回補未在執行，`private/history-session.stop` 仍存在。先核對最新狀態、共享鎖與既有排程，不盲目啟動大量重試。
3. 已知 `127.0.0.1:19385` 的 HTTP／原生 WebSocket 正常，正式 Playwright attach 曾約 15.3 秒逾時；需先恢復正常報表讀取。之前自動重啟專用 Chrome 曾在執行前被工具政策拒絕，實際未重啟。不要繞過拒絕或終止其他 Chrome，必要時請使用者自行恢復專用視窗。
4. 優先補六自有站 1–7 月完整收贈禮／買賣幣，補出營收；其次補全年會員、渠道、機台、活動、儲值包與新舊活躍交集。Win 1/16 開服，開服前不能補零；初期缺日也不能補零。
5. 所有數字必須從後台產出，保留完整日期、查詢／分頁／加總證據與擷取時間。缺值不是 0，不拿今日未結數與前月完整日直接比較，不拿七日外推整月。
6. 官儲與幣商買幣一起追蹤。分別列官儲回購、僅買幣、仍賣幣、未再補入、幣商待核對；前月整月母體與同日數對照分開。競品未確認名冊不能產生正式流失或正式營收結論。
7. 若能操作原機器，優先使用原正式目錄與現有 runtime；公開 clone 的合成名冊僅供測試。正式配置及 DPAPI 憑證只留本地，不上傳、不輸出。
8. 連線及資料就緒後，先跑 `node scripts/history-session.mjs --plan --year 2026` 盤點；經核對再處理自己的 stopfile，先用 `--max-cycles 1` 跑一輪，成功讀回 SHA 後才繼續。不可刪除 `run.lock` 來搶鎖。
9. 每次回報明列新取得的後台來源、實際截止日、更新區塊與剩餘缺口。不要只改生成時間或頁面標籤就說資料補完。

資料發布走既有程式，不需 OpenAI 分析 API，也不需先部署新網站。任何程式修正先跑對應的純函式／fixture 測試；需要私有資料的整合測試必須在有該資料的原環境驗證。
