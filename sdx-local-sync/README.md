# SD × 贏麻了｜白名單電腦同步 B2B 雙神活動測試榜

這個工具在可合法存取 B2B 後台的 Windows 電腦執行，不變更或繞過 IP 白名單。使用的官方資料路徑已依 2026/11/20 的後台畫面確認：

- **累積押碼／投注額榜**：遊戲報表 → 遊戲數據 → 玩家數據。呼叫 `POST /gameSTMT/vendorGamePlayerSTMT`，分別指定廠商、機台、日期，取 `bet`（**總投注額**）與 `nickname`。不得誤拿 `validBet`（有效投注額）、`pay`（總出分）或 RTP。
- **單把最高倍率榜**：遊戲報表 → 帳號查詢。對本次活動 **已登記 AID** 逐一呼叫 `POST /gameSTMT/searchAccountSTMT`，固定廠商、指定機台的 `game_id`、活動期間，逐頁取官方 `xpay`（倍率），每位玩家取最大值。機台 `game_id` 由 `POST /tools/vendorGameList` 的 `id` 取得，與玩家數據的 `gameName` 欄位不同。
- 兩款遊戲獨立計分；前台保留各榜前十名與公開暱稱。每個公開排行榜只傳 `rank,nickname,score`；**不傳 AID、原始注單、姓名、後台帳密或 Cookie**。

## 本機操作（Windows）

程式資料夾：`D:\\StarJournal\\sdx-local-b2b-sync\\`

1. 執行 **首次設定.cmd**，輸入 B2B 密碼，選擇「SD超鑽電子」的 `vendorId`，再選擇正確的「戰神賽特 II 神之庇護」及「雷神之錘」 `gameName`（圖中的雷神之錘顯示 `slot1805`，仍須以後台實際查到的代碼為準）。
2. 在 **`registered_aids.csv`**（本機保留、不上傳 Git）貼上「本次活動」已登記的 AID，每行一筆，第一行是 `AID`。不要匯入上一次活動的登記名單。
3. 執行 **檢查資料.cmd**。程式只印出官方欄位、筆數及試算排行；先確認 B2B「玩家數據」總投注額數字與畫面一致，再核對每個已登記 AID 的最高 `xpay` 倍率。
4. 檢查正確後執行 **啟動同步.cmd**。目前目標每 90 秒開始同步一輪，網站每 30 秒讀取一次最新結果；關閉本機視窗就停止 B2B 同步。
5. 若只想讀取而不發佈，可手動執行 `python sync_b2b.py --dry-run`；`--inspect` 僅顯示欄位名稱和筆數，無個資。

## 特別注意

- 現行正式版只以 Google Sheets 已登記且通過後台驗證的 AID 為統計對象；本機 CSV 是快取，不能以未驗證玩家補齊榜單。
- 首次測試使用你想核對的**本次**日期起點；不要沿用舊活動的 9/8 起算時間。必須先能從白名單電腦連線 B2B（9955 網頁與 9032 API）。
- 程式依官方 `bet` 和 `xpay`，以活動期間過濾倍率注單、依單號去重，並對分頁完整性檢查。查不到、欄位變更、登入失敗或時間不符時，停止發布，不能虛構名次。
- 網站顯示的只是測試榜，不是已核獎結果；獎金、個人成就與資格仍依主辦最終公告。
- B2B 密碼只在本機互動輸入，不寫進 `config.local.json`。`.sync-token` 是私密同步憑證，絕對不要上傳。Render 暫存不具永久性；新版會保留舊榜單並標示「非即時」。更新 Apps Script 後，CCB 與正式活動公開快照會存至 Google Sheets，Render 重啟也能還原。
- 若命令提示字元顯示 `unrecognized arguments: --setup`，代表執行到舊版 `sync_b2b.py`，請確認使用以上指定的工作目錄。


## 新增：破產榜（金幣餘額 ≤ 0.2）

本榜為獨立觀察榜，不影響兩款機台的獎金、個人成就與神運榜，也**不保證有復活金**。

- **來源**：本機 B2B「玩家管理 → 玩家列表」實際會員錢包金幣欄位，對當期 Google Sheets 已驗證登記 AID 做精確匹配；不能從投注額、累積淨輸贏推導餘額。
- **分母**：當期已驗證的參加者數；**分子**：當前金幣餘額小於或等於 0.2 的參加者數。餘額剛好等於 0.2 上榜，0.20001 不上榜。
- **輸贏**：遊戲報表的總出分 pay − 總投注額 bet。戰神賽特 II 與雷神之錘分別顯示，正數「贏」、負數「輸」，不是帳戶餘額。
- **順位**：首次被本機同步偵測破產的順序，保存在此電腦的私密檔案 bankrupt_order.local.json；CCB 清場後活動世代增加，紀錄自動重新計算。目前不符合餘額條件者暫不顯示。
- **AID**：公開頁只顯示遮蔽形式（例如 ******0081），不公開玩家完整 AID、真實姓名、B2B 登入資訊。管理員可至受保護的 Google 登記試算表核對完整 AID。
- **安全**：若 B2B 沒有可靠的金幣欄位、會員資料不完整、權限不足，顯示「等待驗證」，不將未知誤報成 0 人或任何其他比例。

### 第一次啟用

1. 先停止舊版正在執行的 啟動同步.cmd 視窗（Ctrl+C）。
2. 更新本資料夾內的 sync_b2b.py，然後雙擊 **檢查金幣欄位.cmd**，互動輸入 B2B 密碼。程式只會輸出欄位名稱，不會輸出 AID、姓名或金幣數字。
3. 已核對 Winmalo Admin 網頁程式：玩家列表「金幣」欄位對應 `money`，而「洗碼限制」對應 `junket_quota`。新版只採用 `money`。
4. 本機 config.local.json 如有舊的 `memberBalanceField`，必須為 `money`。否則程式會拒絕把其他欄位誤判為金幣。
5. 本機每次成功同步會將 **經隱私過濾** 的破產榜傳到 Render；正式活動中連同其他公開榜單保存至 Google Sheets 的「雙神活動公開快照」分頁，活動結束後不再覆寫。

本次加入功能不會清除既有登記、強制切換活動階段、修改獎金，或保證復活金發放。

## 2026-11-22：改為每 1～2 分鐘更新目標（約 70 名公司參加者）

- 本機 `啟動同步.cmd` 現在使用 `--interval 90`。**90 秒以每輪開始到下一輪開始為目標**，不是查完資料後才睡 90 秒。程式會在每輪顯示實際計算秒數和下一輪預計開始時間。

- 若 B2B 回應順暢，使用者通常在約 1～2 分鐘看到新數據；實際延遲還包括 B2B 計算／API 回應、Google Sheet 保存和網頁下次輪詢，**不是保證秒級即時**。若某次 B2B 同步失敗，網站保留上一版並標示「非即時」。
- **必須重新啟動本機同步**：舊的 Python 視窗不會因檔案更新自動熱切換。先 Ctrl+C 結束舊版，再執行原來的 `啟動同步.cmd`，在本機輸入 B2B 密碼。請保留視窗與已授權的白名單網路連線。

## 2026-11-22：AID 即時驗證服務獨立心跳修復

- 原始問題：排行榜 B2B API 正常、Render 和 Sheets 有資料，但 /api/registration/status 的 verifierOnline=false，導致登記表鎖住。原版驗證器在額外登入 B2B 後，每次串行查詢 AID；任何驗證執行緒無法輪詢超過 35 秒即被判為離線。
- 新版：只登入 B2B 一次；排行榜與查驗共用授權工作階段，使用互斥鎖確保不會同時操作 B2B 會話。
- **獨立心跳**：一條執行緒每 5 秒領取 Render 驗證任務，與玩家倍率／金幣查詢完全分離；另一條執行緒做真正的 B2B player/list AID 檢查。
- **自動復原**：網路或 API 異常時連續重試，避免單次例外令背景執行緒永久死亡；每輪同步會偵測並重啟已停止的背景執行緒。
- **安全**：除精確匹配的已授權 B2B AID 外不能通過；失敗回報 error，不會把「服務離線」誤當成 AID 不存在，不會寫入未驗證登記。
- **可觀測性**：本機新增 verifier-status.json，只有 \`online / reconnecting / stopped\` 與最後時間，不含帳密、AID 或 session。讀取時應看其 updatedAt 是否在 5～15 秒內更新。
- **啟用**：目前開著的舊 Python 程式不會熱套新版檔案。需要使用者在既有視窗按 Ctrl+C，關閉舊進程，重新開 \`啟動同步.cmd\` 並在本機輸入 B2B 密碼。登入後看到「AID 即時驗證心跳已連線」才是完成；接著驗證官網報名按鈕恢復。
- Windows 電腦關機、睡眠、網路斷線、後台故障或 Render 維護時仍可能暫時無法驗證；不能在沒有驗證者的情況下直接開放報名。
